# book_reader — 뷰어

PDF 교재를 읽으면서 막히는 부분을 바로 물어보는 로컬 도구.

왼쪽에 책 원본이 뜨고, 오른쪽에서 질문하면 Claude Code가 책 원문과 (필요할 때) 웹을 뒤져 답합니다.

## 실행

```bash
./setup.sh <PDF 경로>     # 최초 1회
./reader/start.sh
```

서버가 뜨고 브라우저가 자동으로 열립니다. 종료는 터미널에서 `Ctrl+C`.

## 다른 기기에서 보기

이 서버에는 **인증이 없습니다.** 그래서 "어디에 묶느냐"가 곧 접근 제어입니다.
`config.json` 의 `host` 로 정합니다.

| `host` | 누가 닿는가 | 언제 |
|---|---|---|
| `127.0.0.1` (기본) | 이 컴퓨터에서만 | 앞에 앉아서 볼 때 |
| `tailscale` | 내 tailnet 기기에서만 | **태블릿·노트북에서 볼 때 — 권장** |
| `0.0.0.0` | 같은 네트워크의 누구나 | 권하지 않음 |

기동할 때 어느 쪽인지 한 줄로 찍어줍니다.

### 태블릿 + Termux (권장 조합)

전체 설정 절차는 **[docs/termux-setup.md](../docs/termux-setup.md)** 에 정리했습니다.
(SSH 키, `~/.ssh/config`, `.bashrc`, 문제 해결)

요약:

Termux 에서 SSH 로 붙어 서버를 띄우고, 크롬으로 봅니다.

```bash
# 태블릿 Termux 의 ~/.bashrc
MAC=100.85.159.32          # Tailscale IP — 어느 네트워크에서든 같다

alias mac="ssh junho@$MAC"
alias book="ssh junho@$MAC 'cd ~/coding_work/book_reader && ./reader/serve.sh'"
alias bookstop="ssh junho@$MAC '~/coding_work/book_reader/reader/serve.sh stop'"
```

`book` 을 치면 주소가 나옵니다. 크롬에서 그 주소를 열면 됩니다.

**주소는 Tailscale IP(`100.x.y.z`)를 쓰는 편이 안전합니다.** Tailscale 은 오버레이 망이라
같은 와이파이가 아니어도, LTE 로도, 다른 나라에서도 이 주소로 닿습니다.

MagicDNS 이름도 씁니다 — 다만 안정성에 차이가 있습니다.

| 주소 | 언제 되는가 |
|---|---|
| `100.85.159.32` | **항상.** DNS 설정과 무관 |
| `lees-mac-mini.tailea7c23.ts.net` | MagicDNS 가 켜져 있으면 |
| `lees-mac-mini` | 위 + 클라이언트에 search domain 이 잡혀 있으면 |

Termux 는 안드로이드 시스템 리졸버를 타는데 Tailscale 앱의 DNS 설정이
Termux 까지 항상 반영되지는 않습니다. 짧은 이름이 안 풀리면 IP 를 쓰십시오.

`bookstop` 은 **맥에서 도는 서버를 끕니다.** SSH 연결을 끊는 것이 아닙니다
(각 alias 는 명령 하나만 실행하고 알아서 연결을 닫습니다).
읽기를 마쳤을 때 맥에 프로세스를 남기지 않으려고 쓰는 것이고,
계속 쓸 거면 그냥 두어도 됩니다.

**`start.sh` 가 아니라 `serve.sh` 를 쓰십시오.** `start.sh` 는 포그라운드라
SSH 가 끊기면 서버도 같이 죽습니다. `serve.sh` 는 `nohup` 으로 떼어내
연결이 끊겨도 살아남습니다. 태블릿에서는 세션이 자주 끊깁니다.

```bash
./reader/serve.sh          # 기동 (이미 떠 있으면 주소만 알려준다)
./reader/serve.sh stop     # 중지
./reader/serve.sh log      # 로그
```

> **PATH 주의.** `ssh host "명령"` 은 로그인 셸이 아니라서 macOS 기본 PATH 에
> `/opt/homebrew/bin` 이 없습니다. poppler 가 통째로 안 보여
> `기동 실패: pdftoppm 없음` 이 납니다.
> 스크립트와 `config.py` 가 알려진 설치 위치를 스스로 덧붙이므로
> 이제는 그냥 동작합니다. 다른 경로에 설치하셨다면 `EXTRA_BIN_DIRS` 에 추가하십시오.

### Tailscale — 태블릿에서 보기 (권장)

[Tailscale](https://tailscale.com) 은 내 기기들만 들어오는 암호화 사설망을 만듭니다.
거기에만 묶으면 터널도, SSH 도, 앱도 필요 없습니다.

```json
{ "host": "tailscale" }
```

```bash
./reader/start.sh
```

```
  ── 다른 기기에서 바로 열 수 있습니다 ──────────
      http://100.85.159.32:8765
```

태블릿 브라우저에서 그 주소를 열면 끝입니다.
MagicDNS 를 쓰면 `http://<머신이름>:8765` 로도 됩니다.

> LAN 에 여는 것(`0.0.0.0`)과 다릅니다. tailnet 은 **내 계정에 등록된 기기만** 들어오는
> 암호화된 사설망입니다. 카페 와이파이의 옆자리 사람은 닿지 않습니다.

**`tailscale serve` 는?** `https://<머신>.<tailnet>.ts.net` 으로 더 깔끔하게 열 수 있지만,
tailnet 에 **HTTPS 인증서 기능이 켜져 있어야** 합니다. 꺼져 있으면 인증서를 받으려다
멈춥니다 (`your Tailscale account does not support getting TLS certs`).
Tailscale 관리 콘솔 → DNS → HTTPS Certificates 에서 켤 수 있습니다.

## 원격에서 보기 (SSH 터널)

Tailscale 을 안 쓰거나 `host` 를 바꾸고 싶지 않을 때.

책이 있는 머신에 SSH 로 붙어 작업하면서, **눈앞의 노트북 브라우저로** 보고 싶을 때.

서버는 일부러 `127.0.0.1` 에만 묶여 있어 밖에서 직접 닿지 않습니다.
SSH 터널로 통과시킵니다.

**작업 중인 세션은 건드리지 말고**, 노트북에서 터미널을 하나 더 열어:

```bash
ssh -N -L 8765:localhost:8765 junho@<책이 있는 머신>
```

`-N` 은 명령 없이 터널만 유지합니다. 그대로 두고, 노트북 브라우저에서 `http://localhost:8765`.

매번 하기 번거로우면 **노트북의** `~/.ssh/config` 에:

```
Host bookreader
    HostName <IP>
    User junho
    LocalForward 8765 localhost:8765
```

이후로는 `ssh bookreader` 만으로 터널이 함께 열립니다.

`start.sh` 는 SSH 세션을 감지하면 브라우저를 열지 않고(원격 머신에서 열려봐야 소용없으므로)
위 명령을 접속 정보에 맞춰 출력합니다.

### 선결 조건

책이 있는 머신에서 **원격 로그인**이 켜져 있어야 합니다.
macOS: 시스템 설정 → 일반 → 공유 → 원격 로그인.

### `0.0.0.0` 으로 열지 마십시오

간단해 보이지만 이 서버에는 **인증이 없습니다.** 같은 네트워크의 누구든
책을 열람하고, `POST /api/ask` 로 **당신 계정을 써서** 질문을 던질 수 있습니다.
SSH 터널은 이 문제가 없습니다 — 서버는 계속 루프백에만 묶여 있고 SSH 인증을 통과한 사람만 지나갑니다.

## 태블릿에서 화면이 밀릴 때

상단 툴바(목차·영역 선택)가 아래로 끌 때 사라졌다면 `100vh` 때문이었습니다.
모바일 브라우저에서 `100vh` 는 **주소창이 숨은 상태의 높이**라, 주소창이 보이는 동안에는
실제 보이는 영역보다 커서 문서가 그만큼 스크롤됩니다. 아래로 끌면 툴바가 위로 밀려납니다.

`100dvh`(현재 보이는 높이) + `position: fixed` + `overscroll-behavior: none` 으로 고쳤습니다.
이제 문서 자체가 스크롤되지 않고, 스크롤은 책 영역과 대화 영역 안에서만 일어납니다.

## 알아둘 것

**답변은 두 단계로 옵니다.** 요약이 먼저(약 20~30초), 심화는 **＋ 더 자세히** 를 눌렀을 때만
따로 생성됩니다(약 2~3분). 한 번에 다 만들면 첫 글자를 보기까지 3분을 기다려야 해서 나눴습니다.

**기다리는 동안 계속 읽어도 됩니다.** 질문을 여러 개 던져두고 페이지를 넘겨도 됩니다.
답변은 순서대로 처리되어 오른쪽에 채워집니다.

**검색은 수식을 찾지 못합니다.** 추출 텍스트 기반이라 산문만 잡힙니다.

**수식은 드래그로 잡히지 않습니다.** PDF가 수식을 문자로 내보내지 않기 때문입니다.
수식에 대해 물을 때는 **영역 선택**을 쓰세요. 그러면 그 부분을 이미지로 잘라 함께 보내고,
Claude가 원본 페이지 이미지를 직접 읽어 판독합니다.
영역을 안 잡아도 현재 페이지 번호는 항상 전달되므로 "이 페이지 아래쪽 수식" 같은 표현도 통합니다.

**대화 맥락이 이어집니다.** "방금 그거 더 풀어서 설명해줘" 가 통합니다.
길어져서 느려지면 **↺ 대화 초기화**.

## 질문이 어느 페이지에 붙는가

두 페이지가 걸쳐 보일 때 헷갈릴 수 있어 규칙을 정해뒀습니다.

1. **문장이나 영역을 지목했으면 그 자리의 페이지.** p.253을 보다가 스크롤을 올려
   p.252의 문장을 드래그했다면 질문은 p.252에 붙습니다.
2. **아무것도 안 골랐으면 화면에 가장 넓게 보이는 페이지.**

지금 어느 페이지로 판정됐는지는 **초록 테두리**와 입력창 아래
`책 p.253 맥락으로 전송됩니다` 문구로 항상 확인할 수 있습니다.

## 내 질문 다시 찾기

질문이 쌓이면 "여기서 뭘 물었더라"를 찾기 어려워집니다. 두 가지로 해결합니다.

**하나 — 보기(렌즈).** 우측 상단에서 범위를 고릅니다.

```
[ 이 페이지 ] [ 이 절 ] [ 이 장 ] [ 전체 ]
                 ▲ 기본값
```

**절이 기본값인 이유**: 한 개념이 여러 쪽에 걸치기 때문입니다.
한 개념이 예컨대 p.250~255에 걸쳐 있으면, p.252에서 물어본 질문이
p.251로 돌아왔을 때 안 보이면 곤란합니다.
페이지 경계는 조판의 산물이고 절 경계는 의미의 경계입니다.

**답변이 인용한 페이지도 셉니다.** p.252에서 물었는데 답변이 p.250~262를 근거로 들었다면,
p.258을 읽을 때도 그 질문이 보입니다.

**목차·검색 패널은 본문을 덮지 않습니다.** 옆으로 밀어내므로 지면을 보면서 목차를 훑을 수 있습니다.
항목을 고르면 자동으로 닫혀 지면이 다시 넓어집니다. 계속 열어두려면 **고정**을 켜세요.

**셋 — 절별 묶어보기.** '전체'나 '이 장' 보기에서 질문이 여러 절에 걸치면
절 단위로 묶여 접었다 펼 수 있습니다. 그룹 머리의 `p.252` 를 누르면 그 페이지로 갑니다.

**넷 — 삭제.** 각 질문 아래 **삭제**. 한 번 더 눌러야 지워집니다.
완전히 없애지 않고 `qa/trash/` 로 옮기므로 되돌릴 수 있습니다:

```bash
cd qa/trash && for f in *; do d="${f%%-*}"; mv "$f" "../$d/${f#*-}"; done
```

학습 노트(`qa/history.md`)에는 그대로 남습니다. 영구 기록이라 손대지 않습니다.

**둘 — 목차 배지.** `T`를 눌러 목차를 열면 질문한 절에 개수가 표시됩니다.
어디서 무엇을 물었는지 한눈에 보이고, 클릭하면 그 페이지로 갑니다.

### 워커가 프로젝트 밖에 있는 이유

`~/.book-reader-tutor/` 는 일부러 이 프로젝트 트리 **바깥**에 둡니다.
Claude Code는 `CLAUDE.md` 를 상위 디렉터리로 거슬러 올라가며 찾기 때문에,
워커를 저장소 안에 두면 개발 규칙 전체가 매 질문마다 로드됩니다.
책에 대한 질문에 개발 워크플로 규칙은 필요 없습니다.
실측으로 질문당 약 9,300 토큰 차이가 났습니다 (트리 안 22,759 / 밖 13,410).

## 문제 해결

**포트 8765가 사용 중**
```bash
lsof -nP -iTCP:8765 -sTCP:LISTEN     # 무엇이 쓰는지 확인
```
