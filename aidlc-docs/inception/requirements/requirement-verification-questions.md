# 요구사항 확인 질문 (Requirements Verification Questions)

각 질문의 `[Answer]:` 태그 뒤에 알파벳을 적어주세요. 맞는 선택지가 없으면 마지막 옵션(Other)을 고르고 설명을 적어주시면 됩니다.
전부 답하신 후 "done"이라고 알려주세요.

---

## 배경: 왜 이 질문들이 필요한가

요청하신 것은 "좌측에 책 내용, 우측에서 질문하면 바로 답변"입니다.
여기서 **"누가 답변을 만드는가"** 가 정해지지 않으면 설계가 진행될 수 없습니다.

HTML 페이지는 그 자체로 사고할 수 없습니다. 답변은 반드시 어딘가의 LLM이 만들어야 하고,
그 LLM이 **책 본문과 웹 검색에 접근할 수 있느냐**가 답변 품질을 좌우합니다.
Q1이 이 프로젝트에서 가장 중요한 결정입니다.

## Question 1: 답변 엔진 아키텍처 ⭐ 핵심

우측 패널에서 질문했을 때, 누가/어떻게 답변을 생성할까요?

**A) 로컬 뷰어 + 터미널 Q&A (가장 단순)**

HTML은 순수 읽기 전용 뷰어. 질문은 지금처럼 Claude Code 터미널에 직접 입력.
- 장점: 오늘 바로 완성. 책 원문 검색 + 웹 검색 + 대화 맥락 전부 활용 가능. 추가 비용 0.
- 단점: 화면을 왔다갔다 해야 함. "우측 패널에서 바로" 라는 요청과는 거리가 있음.

**B) 로컬 뷰어 + 파일 큐 + Claude Code 폴링 루프 (추천)**

HTML 우측 패널에 질문을 입력하면 → 로컬 미니 서버가 질문을 파일로 저장 →
Claude Code가 주기적으로(예: 20초) 그 파일을 확인해서 답변 생성 → 답변 파일을 페이지가 읽어 우측에 표시.
- 장점: **페이지 안에서 질문/답변이 완결됨.** 답변하는 주체가 Claude Code이므로
  `refs/nc.sh`로 책 원문을 뒤지고, 필요하면 PDF 페이지를 이미지로 직접 읽고(수식·회로도),
  웹 검색까지 전부 동원한 **가장 품질 높은 답변**이 나옵니다. 추가 API 비용 0.
- 단점: 답변까지 수 초~수십 초 지연(폴링 주기). Claude Code 세션이 켜져 있어야 함.
  구성 요소가 3개(HTML + 미니 서버 + 폴링 루프)로 조금 늘어남.

**C) Artifact + 페이지 내장 Claude 호출**

claude.ai에 호스팅되는 Artifact로 만들고, 페이지가 자체적으로 Claude에게 질문.
- 장점: 링크만 있으면 어디서든(폰 포함) 접속. 터미널/서버 불필요. 지연 짧음.
- 단점: 페이지에 내장된 Claude는 **웹 검색과 PDF 원본 접근이 안 됩니다.**
  책 내용을 답변에 쓰려면 본문 텍스트를 페이지에 통째로 넣어야 하는데,
  이는 저작권이 있는 교재 전문을 호스팅하는 것이라 **권장하지 않습니다.**
  (Artifact는 기본 비공개지만 링크 공유가 가능한 구조입니다.)

**D) 로컬 서버 + Anthropic API 직접 호출**

Python 백엔드를 만들고 내 API 키로 Claude API를 호출. 웹 검색·책 검색 도구도 직접 구현.
- 장점: 완전히 독립 실행. 지연 짧음. Claude Code 세션 불필요.
- 단점: API 키와 **토큰 비용이 실제로 발생.** 도구(책 검색/웹 검색)를 직접 구현해야 해서
  구현량이 가장 많음. 사실상 에이전트를 처음부터 만드는 작업.

**X) Other** (직접 설명)

[Answer]: D. 내가 CLI에서 질의 하듯이, HTML에서의 질의를 claude code가 PDF와 웹을 기반으로 답변하면 돼

## Question 2: 좌측 본문 표시 방식

Nielsen & Chuang 본문을 왼쪽에 어떻게 띄울까요?

**A) PDF 원본 렌더링 (pdf.js)**

원본 그대로. 수식·양자회로 그림·표가 **완벽하게** 보입니다.
텍스트 선택/검색도 됩니다. 양자컴퓨팅 교재 특성상 수식이 핵심이라 가장 안전한 선택.

**B) 추출된 텍스트 (refs/nielsen-chuang.txt)**

가볍고 빠르고 검색·복사가 쉽지만, **수식이 깨집니다.**
(예: 이미 확인된 사례 — "Hardness of approximation of ▨" 처럼 TSP 기호가 소실)
양자역학 교재에서는 치명적인 단점입니다.

**C) PDF 렌더 + 텍스트 병행**

PDF를 기본으로 보여주되, 선택한 페이지의 추출 텍스트도 접어서 볼 수 있게. 구현량 소폭 증가.

**X) Other** (직접 설명)

[Answer]: C

## Question 3: 질문에 페이지 맥락을 자동으로 붙일까요?

"이 부분이 이해가 안 돼"라고 물었을 때 '이 부분'이 어디인지 아는 방법입니다.

**A) 현재 보고 있는 페이지 번호를 자동 첨부**

질문에 "지금 책 p.252를 보는 중" 정보가 자동으로 따라붙습니다. 구현 간단, 효과 큼.

**B) 페이지 번호 + 드래그로 선택한 텍스트 첨부**

본문에서 특정 문장을 드래그한 뒤 질문하면 그 문장이 그대로 질문에 포함됩니다. 가장 정확.

**C) 아무것도 첨부하지 않음 — 질문만 그대로 전달**

[Answer]: B

## Question: Resiliency Extensions

Should the resiliency baseline be applied to this project?
(복원력 베이스라인을 적용할까요?)

**이 확장이 무엇인지.** 활성화하면 **AWS Well-Architected Framework (Reliability Pillar)** 에서 파생된
**방향성 있는 설계 시점 모범 사례** 집합이 적용됩니다. 요구사항·설계·코드를 내결함성, 고가용성,
관측 가능성, 복구 가능성 쪽으로 유도하며, 비즈니스 목표·변경 관리·관측성·고가용성·재해 복구·지속적 개선에 걸친

**이 확장이 아닌 것.** 활성화한다고 워크로드가 프로덕션 준비 상태가 되지 않으며,
