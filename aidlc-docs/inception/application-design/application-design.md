# Application Design — N&C 리딩 어시스턴트 (통합)

> 상세는 `components.md`, `component-methods.md`, `services.md`, `component-dependency.md` 참조.

## 1. 한 문장 요약

브라우저가 책 페이지를 그리고, 파일시스템이 메시지 큐가 되며, `claude -p` 가 질문마다 짧게 태어나
책 원문과 웹을 뒤져 답을 남기고 사라진다. 상주하는 것은 미니 서버 하나뿐이다.

## 2. 설계를 결정한 실측치

이 설계는 추측이 아니라 코드 작성 전에 돌린 실험 10건 위에 서 있다.

| 측정 | 값 | 설계에 미친 영향 |
|---|---|---|
| `--permission-mode dontAsk` 단독 | **도구 전면 거부** | `--allowedTools "Bash Read WebSearch"` 필수화 |
| `--allowedTools` 추가 후 | 통과, 정답 반환 | 파이프라인 성립 확인 |
| PDF 페이지 이미지 판독 | 6.1초, 수식 LaTeX 정확 | 텍스트 추출의 수식 소실을 우회 |
| WebSearch | 컷오프 이후 데이터 반환 | 실제 검색 동작 확인 |
| `pdftoppm` 렌더 | 0.209초 / 308KB / 수식 선명 | 서버 사이드 렌더 채택 |
| `pdftotext -bbox` | 단어별 좌표 제공 | **투명 텍스트 레이어 → 의존성 0으로 드래그 선택** |
| `pdftoppm` 크롭 | 0.039초, 수식만 정확히 분리 | 영역 선택(Q6=B) 구현 가능 |
| KaTeX 벤더링 | ~592KB (js+css+woff2) | 수식 렌더 채택 |
| `--json-schema` | 유효한 구조화 출력 | 답변 계약 신뢰 가능 |
| **깊은 질문 1건 전체** | **144,951ms / 9턴** | **답변 생성을 2단계로 분리** |
| AI-DLC 트리 안/밖 | 22,759 / 13,410 토큰 | 워커를 `~/.qc-book-tutor/` 로 격리 |

## 3. 컴포넌트

| | 무엇 | 어디 |
|---|---|---|
| **C1** | 뷰어 (바닐라 JS + KaTeX) | `qc_book/reader/` |
| **C2** | 미니 서버 (Python 표준 라이브러리) | `qc_book/reader/server.py` |
| **C3** | 답변 워커 (`claude -p` 래퍼) | `~/.qc-book-tutor/` ← **AI-DLC 트리 바깥** |
| **C4** | 파일 계약 | `qc_book/qa/` |

의존은 단방향이다. 뷰어는 워커를 모르고, 워커는 뷰어와 서버를 모른다.
셋을 잇는 것은 `qa/` 디렉터리의 파일뿐이다.

## 4. 요구사항 추적

| 요구사항 | 어떻게 충족되는가 |
|---|---|
| FR-1 책 본문 | `pdftoppm` 150dpi PNG, 책 페이지 번호 표시 (변환은 서버에서만) |
| FR-2 추출 텍스트 | `refs/nielsen-chuang.txt` 슬라이스, 접이식 패널 |
| FR-3 선택 캡처 | 투명 텍스트 레이어 드래그 **+ 영역 사각형 선택**(크롭 이미지) |
| FR-4 질문 전송 | 페이지 번호 + 선택 문장 + 영역 이미지 자동 첨부 |
| FR-5 단계적 답변 | **생성 자체를 2단계로 분리** — 요약(15~30초) → "더 자세히"(60~150초). KaTeX 렌더 |
| FR-6 기록 축적 | `qa/history.md`(사람) + `qa/*.json`(기계) 이중 기록 |
| FR-7 위치 복원 | `qa/state.json`, 페이지 이동마다 저장 |
| FR-8 유실 방지 | 질문 파일이 먼저 기록됨. 실패해도 남아 재시도 가능 |
| FR-9 조사 파이프라인 | `nc.sh` → PDF/크롭 이미지 판독 → 필요시 웹 검색 |
| NFR-1 실행 환경 | `qc_env/bin/python`, 표준 라이브러리, localhost |
| NFR-2 단순성 | 상주 프로세스 1개, WebSocket 없음, 프레임워크 없음. **KaTeX만 예외** |
| NFR-3 응답성 | 논블로킹 + 2단계 분리로 첫 응답까지의 체감 시간 최소화 |
| NFR-4 데이터 소유 | 전부 로컬. 런타임 네트워크는 웹 검색뿐 |
| NFR-5 비용 | API 키 없음. 구독 세션으로 동작 |
| NFR-6 상태 명확성 | `pending/running/summary_ready/detail_ready/error` + 대기 건수 표시 |
| NFR-7 규칙 격리 | 워커를 AI-DLC 트리 바깥에 배치. 실측 9,300 토큰 절감 |

## 5. 남은 위험

| 위험 | 대응 |
|---|---|
| 요약 단계가 목표(30초)를 넘길 수 있다 | 워커 지침에서 요약 단계의 도구 사용을 제한. Build and Test에서 실측 후 조정 |
| 고정 세션이 길어지면 매 호출이 느려진다 | "대화 초기화" 버튼으로 새 UUID 발급 |
| 텍스트 레이어가 수식에서 끊긴다 | 설계상 수용. 영역 선택으로 보완 |
| KaTeX가 NFR-2를 흠집낸다 | 사용자가 Q1에서 명시적으로 선택 ("수식을 읽는데 불편함이 없어야 해") |
